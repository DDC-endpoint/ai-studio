## Checked and clean

- **Prompt injection.** The curate prompt wraps the general caption in `fenceUntrusted(general)` and appends `UNTRUSTED_CONTENT_GUARD` to the system prompt, only when a general caption is carried. The block sits in the user message after the rules.
- **New routes.** `DELETE .../captions` and `POST .../captions/undo` check body or query shape (400), then `canView` (404), then `canEditPost` (403 `NOT_AUTHOR`), and only then write. Neither calls `track`, so no caption text reaches analytics. Both are `edit` in `POST_ACTION_TIERS`, and `visibilityBoundary` asserts that both import `visibility`.
- **Limiter.** `admitCaptionAction(user.userId)` runs after the tier and not-ready gates and before model resolution and the claim, keyed by user. 429 carries `Retry-After`. The seam is 404 in production and without `MOCK_AI`, admin-gated, and body-validated.
- **Limiter extraction.** `createWindowLimiter` has the same sweep, filter, refuse-not-recorded and push logic as the old `allow`, and `analyticsRateLimit.test.ts` is unchanged and green. Behaviour is identical.
- **Store.** `deleteCaption` returns `missing` for an absent or already-deleted row and `pending` for PENDING. It removes an empty row and soft-deletes a row with text, with `previous` saved. Every write is guarded on `updatedAt`. `undoCaption` swaps live state and `previous`, keeps the general caption undeleted regardless of the snapshot, and answers `changed` on a lost race. Both call `refreshAfterWrite`, and the AC-15 scan passes.
- **Hash.** `generalHashOf` hashes the trimmed text. The settle stores it on curated rows only, and null when no live general caption exists (D11).
- **UI.** Delete, Undo and the edit controls are behind `canEdit`. Undo shows only while `canUndo`. A deleted card shows "Deleted" and Undo. The rules and facts lines use `Notice` with no raw colours, and the token and wording guards pass.
- **Guards.** The `factsSourcesBoundary` fixtures (aliased, relative and `prisma.draftCaption` imports) fail as AC-16 requires, and the real file passes.

## Findings

### [NOTE] src/lib/captions/store.ts (deleteCaption) and src/app/api/drafts/[id]/captions/route.ts — Correctness (edge)

**Problem:** A delete that loses a write race (`count !== 1`) returns `'pending'`, which the route answers as "This caption is being generated" (409). The cause was a concurrent edit, not generation. The design's result set (`deleted | removed | pending | missing`) has no `changed`, so this follows the contract, but the message is misleading.
**Suggestion:** Answer 409 with a neutral "The caption changed. Try again." for this case, or leave as is.

### [NOTE] src/components/drafts/CaptionPanel.tsx — Naming (wording)

**Problem:** The Undo, Delete and Copy aria-labels use `noun`, which is fine. The T2 note about `title` in labels is not yet applied to Copy and Regenerate. It is a carry-over, not new in T3.
**Suggestion:** Fold into the T2 note's follow-up.

### [NOTE] src/lib/agent/prompts/caption.ts:~93 — Complexity (formatting)

**Problem:** The `task` ternary chain is nested with the `curate && curated.length === 1` branch left unindented, so it reads as two separate ternaries. Prettier reflow was applied to whole touched files (deviation 5), which inflates the diff in `store.ts`, `requests.ts` and the route and makes review harder.
**Suggestion:** None required; parenthesise or extract the task line if touched again.
