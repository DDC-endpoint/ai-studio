## Findings

### [NOTE] src/components/drafts/CaptionPanel.tsx:~189 and ~203 — Naming (wording)

**Problem:** `const title = \`${spec.label} caption\`` gives "General caption", and the Copy and Regenerate buttons use it in aria-labels (`Copy ${title}`, `${verb} ${title}`) and the picker label (`${title} model`). Mid-sentence that reads "Copy General caption", while the same panel uses the lower-case `noun` ("general caption") for its notices. DESIGN_SYSTEM §12 keeps the general caption lower case in a sentence. The wording guard does not catch it because the string is built, not a literal.
**Suggestion:** Use `noun` in the `aria-label`s (`Copy ${noun}`), and keep `title` for the heading only. Check the E2E locators that read these names first (TC-CAP-23 to 26).

### [NOTE] src/lib/captions/store.ts (claimCaptionAction) and src/app/api/drafts/[id]/regenerate-copy/route.ts:~148 — Correctness (edge)

**Problem:** The row of a general caption is created inside the claim. If `startDraftAction` then throws before the run starts (the 422 `copyError` path), the catch settles the target rows as failed, so an old post is left with an empty FAILED general row instead of none. It is harmless (the panel shows the failure notice with Generate), and no row is made on a 4xx before the claim, but "a 4xx creates nothing" is not literally true for a 422 after the claim.
**Fix:** None needed. If the user sees this as surprising, delete a row that `created` names and that is still empty when the claim is released.

### [NOTE] src/lib/drafts/detail.ts:~199 — YAGNI (placeholder)

**Problem:** `const kitWebsite: string | null = null` and the matching `website = null` in `captionList` are stubs for T4. They are commented, and the response key is stable, so no harm.
**Fix:** T4 replaces both; add `src/mcp/tools/generate.ts` to T4's Files list so the MCP path is not forgotten.
