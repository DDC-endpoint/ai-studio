# Review T5 (039-general-and-curated-captions), mode full

Spec compliance: D22, D23, FR-19, FR-20, AC-21 and AC-22 are met. T6 is correctly absent. I ran analyticsCoverage, analyticsEventsRoute, analyticsQueries, uiTokenGuard and uiWordingGuard: 130 passed. I did not run E2E or touch the database.

## Checked and clean

- **Deviation 1 (400 before 404).** The 400 comes from the payload schema (kind/channel pair, WHATSAPP) and depends only on the body, never on the draft. A caller learns nothing about a draft's existence from it. A foreign, missing, non-string or over-64-char `draftId` all give the same 404 with nothing written. Accepted; the design order was 404 first, but the difference is not observable across teams.
- **Deviation 2 (legacy events).** A pre-039 REGENERATE_COPY event with a channel and no `captionKind` counts as CURATED, and the WHERE clause drops rows with neither. Correct, since only Instagram and LinkedIn existed then.
- **Route order.** Unknown name 400, payload 400, then the 60/min window (applies to both events, drop counted), then the draft check, then the 10 s dedupe, then the single `track`. Team, user and source come from the session; the body supplies only `draftId` and the enum payload. `wizard.step` code is untouched.
- **Dedupe map growth.** Keys are written only after the draft passed the team check, so an attacker cannot mint keys for foreign or unknown ids. The limiter sweeps stale keys above 1000 entries. Bounded by user x own-team drafts x 3 entries, and the 60/min window caps the insert rate.
- **Client.** `sendCaptionCopied` is fire-and-forget with `.catch` and try/catch, and sends enums and the draft id only. `CaptionPanel` returns on a clipboard failure before sending and sends after the success toast.
- **One emitter and vocabularies.** One `track('caption.copied'` literal, in the route; the coverage fixture asserts a second file gives 2 hits. The schema imports `CaptionKind`, `Channel` and the registry rather than copying them, and refuses a retired channel.
- **Insights.** `captions()` joins the existing `Promise.all`, five bounded, range-limited aggregate queries with no per-row work (the same pattern as the neighbours). `shapeCaptions` returns one row per registry entry in order, with zeros. The page and API remain super admin (the section only extends `insights()`). Copy says "Copied (client-reported)", sentence case, no chart; the uiToken and wording guards pass.

## Findings

### [NOTE] src/lib/analytics/queries.ts (curated query) — Correctness (edge)

**Problem:** `count(DISTINCT "draftId")` over curate-create events in the window is divided by `generation.finished ok` in the same window. A post generated before the window and curated inside it raises the numerator only, so the rate can pass 100% on a short range. The design specifies exactly this, so it is a known limit, not a defect.
**Suggestion:** Say so in the T6 docs or clamp the display; no code change required.

### [NOTE] src/lib/analytics/queries.ts (written count) — Correctness (edge)

**Problem:** General "written" is `generation.finished ok` plus REGENERATE_COPY events with `captionKind = 'GENERAL'`. A pre-039 regenerate-copy event that carries a channel but no `captionKind` is counted as CURATED, so the Instagram and LinkedIn "written" numbers for old events are slightly mixed with curated semantics. Harmless; legacy only.
**Suggestion:** None.

## Verdict Rationale

The new client event is session-scoped, team-checked before any write, deduplicated with a bounded map, and carries enums only. The one-emitter guard and the legacy handling hold, the Insights queries follow the existing bounded-aggregate pattern, and the tests and UI guards pass. Only notes about edge behaviour that the design accepts remain.
