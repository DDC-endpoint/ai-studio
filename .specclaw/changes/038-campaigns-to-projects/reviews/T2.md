## Findings

### [WARN] src/app/api/projects/[id]/route.ts:24,33,60,67,98 and briefing/documents routes — NFR-07 / spec line 115

**Problem:** The spec fixes one body for unknown, deleted and foreign project ids: `{ error: 'Project not found', code: 'PROJECT_NOT_FOUND' }`. Only the library filter does that. The project routes return `{ error: 'Not found' }` (route.ts GET/PATCH/DELETE; briefing `[vid]/activate`; `documents/[docId]`) or `{ error: 'Project not found' }` with no `code` (briefing, chat, enhance, upgrade, documents). So status matches but the body differs between surfaces, which NFR-07 forbids. A client can tell the library 404 apart from the project 404, though not existence, so the oracle risk is low; it is a contract deviation.
**Fix:** One shared helper/constant returning the spec body, used by every project route (it will be needed by T3's brief route and T4 anyway), and add a body assertion to `projects.test.ts`.

### [NOTE] src/app/api/projects/[id]/route.ts:96-107 — D9 delete race

**Problem:** `updateMany` unassigns, then `project.update` soft-deletes, at read-committed isolation. A concurrent assign (T4) that passes its `isDeleted:false` check between the two statements leaves a brief on a soft-deleted project (the SET NULL FK fires only on hard delete). Not reachable until T4 adds the assign route.
**Suggestion:** In T4, have the assign write conditional on the project being live (e.g. `updateMany` where the project is not deleted) or re-check inside a transaction; or order project soft-delete first inside the tx so the assign's check sees it.

### [NOTE] src/app/api/projects/[id]/documents/route.ts:62-68 — cap check not atomic

**Problem:** `count` then `create` allows two parallel uploads to exceed 5 documents. Carried over unchanged from the campaign route; not a regression.

### [NOTE] src/app/api/projects/[id]/route.ts:20 — postCount semantics

**Problem:** `_count.briefs` counts every brief with the project id, including briefs with no draft yet. The delete dialog's "N posts" and the section count could differ slightly from the library list under `projectId`. Acceptable for D9; mention if AC-14 compares them.
