## Findings

### [WARN] tests/unit/visibilityBoundary.test.ts:1 — Test quality (spec FR-04)

**Problem:** FR-04 asks for a read-boundary walk: every file under `src/app/**` and `src/mcp/**` that queries `prisma.draft` or `prisma.brief` must import `@/lib/authz/visibility` or be on a reasoned allow-list. The file instead tests only that `visibility.ts` is pure (`it('imports nothing but a type'`, `'does not read a campaign or the database'`). A new route that reads drafts with a bare `{ teamId }` or no check at all would pass every unit test. `grep` shows about 20 such files today, so the walk is feasible.
**Fix:** Add the walk with the three allow-list entries the spec names (dashboard "Posts this month", MCP/ACP tools, `src/lib/agent/**`). Keep the purity test if wanted.

### [NOTE] tests/unit/postActionTiers.test.ts:55 — Test quality

**Problem:** The predicate check is a presence test (`/canEditPost\(/.test(src) && /NOT_AUTHOR/.test(src)`, `/canView\(/`). It does not check that `canView` comes before `canEditPost`, or that the 403 comes before side effects, so a reordering would pass. The `none` tier asserts only "no NOT_AUTHOR". `briefs/screenshots GET` is typed `none`, but the spec calls it view and the code does the check through `draftVisibilityWhere`. The test does not require any visibility predicate for it.
**Suggestion:** Assert `src.indexOf('canView(') < src.indexOf('canEditPost(')` for edit handlers. Tier the screenshots GET as `view` and accept `draftVisibilityWhere(` there, as FR-03 allows.
