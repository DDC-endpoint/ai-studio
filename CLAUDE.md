## What this project is

A Next.js 16 + TypeScript web app that turns a brief into a finished, on-brand, social media post image to download, with a general caption and curated Instagram, LinkedIn and Facebook captions to copy. Two generation paths:

- **Path A** — HTML/CSS brand template (stored in DB), Claude agent fills it → Puppeteer renders PNG
- **Path B** — Claude agent generates freeform HTML/CSS design → Puppeteer renders PNG

Stack: Next.js 16, TypeScript, Prisma, PostgreSQL, MinIO, better-auth (self-hosted), Docker Compose. Puppeteer (headless Chromium) for HTML→PNG rendering. Claude agent harness (Anthropic SDK tool-use loop) drives design generation.

## Architecture decisions to remember

> The 037–039 program (see "Current state") removed scheduling and publishing (037, verified) and replaced campaigns with projects (038, verified). 039 (general and curated captions) is built and not yet verified; the caption entries below describe it.

- All AI calls are **server-side only** — the browser never calls an AI API or Puppeteer directly
- **Roles are hierarchical:** `SUPER_ADMIN > ADMIN > EDITOR`; every check goes through `hasRole()` (`src/lib/roles.ts`) — never compare role strings directly. Super-admins pass every admin gate. User management (`/admin/users`) is super-admin-only; "delete" = deactivate (`User.disabled`, sessions revoked, sign-in blocked).
- **Sign-in is by username** (better-auth `username()` plugin); email exists internally only (`<username>@users.bistec.internal` synthesized for admin-created accounts). Seeded dev admin: `adminBTG`.
- **Accounts are admin-created only (034):** a user is created by a super admin (`POST /api/admin/users`, which calls `auth.api.signUpEmail` server-side) or by the seed scripts, never by public sign-up. `src/app/api/auth/[...all]/route.ts` passes only an allow-list of better-auth method and path pairs (`sign-in/username`, `sign-in/email`, `sign-out`, `change-password`, `get-session`) and answers 404 to everything else, sign-up included; add a path there only on purpose. better-auth's `disableSignUp` is not used: it would also refuse the admin route's server-side call. `POST /api/briefs/images` requires a team (`withTeamAuth`).
- **Brand kit precedence (038):** explicit brief kit (`Brief.brandKitId`) → project default kit → team default (`BrandKit.isDefault = true`). `resolveBrandKit(teamId, { brandKitId, projectId })` is called only through `src/lib/projects/context.ts` (plus the look probe, which builds its own empty context); `kitResolverBoundary.test.ts` fails on any other caller. A soft-deleted project recorded on a draft still supplies its kit.
- **Access tiers (038):** one principle: every team member views every post; only the author or a team admin edits. `canView` and `canEditPost` live in `src/lib/authz/visibility.ts` (pure) and every post route gets its tier. A non-member gets 404; a member who may not edit gets 403 `NOT_AUTHOR`. `POST_ACTION_TIERS` (`src/lib/authz/postActionTiers.ts`) lists each draft action route's tier (`view`, `edit` or `none`), and `postActionTiers.test.ts` fails on a route missing from it; `visibilityBoundary.test.ts` fails if `visibility.ts` stops being pure or a file that queries drafts or briefs neither imports it nor is on the allow-list. The draft GET returns `canEdit`, and the post page and library card hide edit controls when it is false. An editor may delete their own post.
- **PostContext (038):** the inputs a post was generated from (project id, briefing version, kit id) are recorded on `Draft.generationInputs` (schema and `sameInputs` in `src/lib/projects/inputs.ts`, pure). A generation call takes a `PostContext`, a branded type that only `src/lib/projects/context.ts` can build (`newPostContext` for a new post, `postContext(draft)` for a retry, regenerate, refine or facts-check refresh); `postContextSites.test.ts` fails when a generation call site builds inputs another way. That file is also the only reader of `ProjectBriefing`. Moving a post to another project only relabels it; `POST /api/drafts/[id]/apply-project` (edit tier, compare-and-set on the stamp; 409 `busy`, `no-change` or `changed`) is the one way to take the project's current inputs, and it recomputes the facts check.
- **Assign and apply (038):** `PUT /api/drafts/[id]/project` (view tier: any member) writes `Brief.projectId` in a transaction that locks the live target project (a foreign, deleted or unknown id is 404 `PROJECT_NOT_FOUND`). Events, one emitter each: `draft.project_changed` (`change`, `fromProjectId`, `toProjectId`; a no-op emits nothing) and `draft.inputs_applied` (`fromProjectId`, `toProjectId`, `kitChanged`, `briefingChanged`, `factsStatus`). Project delete soft-deletes first, then unassigns its posts, and reports `{ unassigned }`. A team holds at most `MAX_PROJECTS_PER_TEAM` (200) projects (409 `project-limit`). The library filters by project, kit and post style (`projectId=none` is unassigned).
- **Post size:** chosen per brief (`Brief.aspectRatio`: `SQUARE`=1080×1080, `PORTRAIT`=1080×1350); a brand template declares the size it was designed for (`BrandKitTemplate.aspectRatio`). Dimensions resolve through `src/lib/aspectRatio.ts` — the only place pixel sizes are defined.
- **AI provider resolution order:** Brief's chosen key → `AvailableProvider.isDefault` → env var fallback
- **Claude model resolution (008):** one catalogue, `src/lib/models/catalogue.ts`, is the only place a model ID or alias may appear in `src/` (a guard test enforces it). Every call names a surface and resolves through `resolveModel`: explicit pick (or the brief's stored initial request) → the draft's stamp (regenerate only) → the team default (`/team` → Models) → the system default (`CLAUDE_CLI_MODEL` in CLI mode, then the table) → fallback. The team allow-list is checked at every tier at call time; only an explicit pick returns 400, and a stored value that is no longer allowed is substituted and recorded. Choices are stored as keys (`HAIKU`/`SONNET`/`OPUS`); stamps record the full ID that ran.
- **Fonts (031):** the Google Fonts catalogue is a snapshot, `src/lib/fonts/catalogue.json` (dated 2026-10-26; 1950 families; never fetched at runtime). `src/lib/fonts/catalogue.ts` holds the lookup `findFamily`, `url.ts` builds the request with `googleFontsUrl`, and save validation runs in `validateKitFonts` and `validateScriptFonts`. A kit's `BrandKit.scriptFonts` (Sinhala only, empty by default) feeds the font stacks through `scriptFonts`. At the three design writers (Path A, Path B and refine) `applyPostFonts` (`src/lib/fonts/inject.ts`, pure) adds the marked font request and the stack entries; a guard test covers the call sites. A family that does not render is recorded in `renderNotes.fontsMissing` on the stamp and shown as a notice. `/api/fonts` serves the picker. Refresh the snapshot with `node scripts/refresh-google-fonts.mjs`, an operator step (see `docs/cold-start.md`); it never runs in CI and never removes a family (it marks a missing one `delisted`).
- **Image generation key (031):** a user can connect a personal OpenAI or Gemini key at `/settings`, stored in `UserOpenAiKey` with a new `provider` column (additive; `openai` for old rows). `detectKeyProvider` (`src/providers/keyPrefix.ts`, pure, shared by the server, `/team` and the card) decides the provider from the prefix; an unknown prefix is refused with 400 and nothing is stored. The resolver (`resolveImageProviderWithSource`) tries the personal key first, falls back once to the team provider with a notice, and stamps `Draft.imageSource` with the tier that served the image. The live Gemini call is not verified (mock only, L1).
- **Apply to image (031):** `src/lib/applyText/` (candidates, the splice, the append-only failure list `APPLY_FAILURES`) and the route `POST /api/drafts/[id]/apply-text`. It runs only on a `stale` headline (422 `not-stale` otherwise), claims the draft under the `APPLY_TEXT` action, splices the new headline into the HTML with `parse5` and renders it through `commitDraftRevision` with `acceptRender`. The in-render check (`src/lib/renderedText/`, T14) is fail-closed: a render where the new headline is not painted, or the old one still is, writes nothing and names the reason. The event is `draft.text_applied` (no text in the payload). `APPLY_TEXT_BETA` is `false`: the re-measure on `bistec_studio_op1` passed 35 of 36 (97.2%, a non-representative sample), so there is no Beta chip. Undo restores the previous revision.
- **Wording guard (031):** the glossary is `docs/ui-reference/DESIGN_SYSTEM.md` §12 "Words" ("post", not "brief"; Template and Freeform; Brand kit; Team settings; sentence case; US spelling). `tests/unit/uiWordingGuard.test.ts` scans string literals and JSX text in `src/app/(app)/**` and `src/components/**` against `WORDING_PATTERNS`, and fails on a deny-listed phrase. A line opts out only with `// wording-exception: <reason>`. Messages in `src/lib` are fixed by hand, not by the guard. Routes, API fields and DB names do not change.
- **Hero imagery (009):** a Path B brief carries an optional `Brief.imageStyle` (`classic` default, `product-showcase`, `editorial-split`, `full-bleed-scene`, `spotlight`). Since 028 every current look supports SQUARE, PORTRAIT and STORY, so 9:16 is no longer excluded for interactive Path B briefs; MCP and ACP briefs are always classic. `src/lib/designData/` is the single source of the layout regions (007 extends it). Every draft and revision carries a `composition` stamp (null means "before 009"). A hero image that fails the real-pixel check fails closed: it is reused under the classic prompt, with no second image call.
- **Worker health (023, reduced by 037):** the worker container (`scheduler`) runs one loop, `retention`, which writes a `WorkerHeartbeat` row through `runTick` (`src/scheduler/loops.ts`). The Insights Health line shows it ("Retention running", "stalled" or "never ran", from `OFFLINE_THRESHOLD_MS` in `analytics/queries.ts`). `GET /api/scheduler/status` and the "Scheduler offline" banner are gone. The seam `POST /api/test/worker-heartbeat` accepts only `loop: 'retention'` (400 otherwise).
- **Caption registry (039, replacing 026):** `CAPTION_REGISTRY` in `src/lib/channels.ts` is the one list: the general caption, then Instagram, LinkedIn and Facebook. `CAPTION_CHANNELS` is its curated subset. Each entry holds its label, reply key, hard limit, rules (words, hashtags, link) and fact-check place. **Kinds:** `DraftCaption.kind` is `GENERAL` (no channel, at most one live row per draft) or `CURATED` (one live row per draft and channel), enforced by two partial unique indexes and two CHECK constraints. Only `FACEBOOK` was added to `Channel`; WhatsApp is in `RETIRED_CHANNELS`, so old WhatsApp rows are hidden by the loader and never deleted. **Derived, not copied:** `FACT_WHERE` (`src/lib/factsCheck/types.ts`), the prompt's reply keys and rules text, and the model token budget (`captionMaxTokens(targets)`) all come from the registry; `captionRegistryGuard.test.ts` fails on a `Channel` value that is neither in the registry nor retired, and on a registry entry that is not in the enum. **One reader:** every read of caption rows goes through `loadDraftCaptions` (`{ general, curated }`, which creates nothing). **Every writer** ends in `refreshAfterWrite`, which recomputes the facts check; `captionWriters.test.ts` fails on a writer without it. A bulk caption write is scoped to registry channels. **Edit, replace, undo:** an edit or a successful curate or regenerate stores the earlier text in `previous` (identical text writes nothing), and `POST /api/drafts/[id]/captions/undo` swaps the two, so a second undo swaps back. **Delete** (`DELETE /api/drafts/[id]/captions?channel=`) is soft (`deletedAt`); a deleted caption leaves the editor, the facts check and the MCP and ACP list, and undo brings it back. The general caption cannot be deleted. **Facebook:** `composeFacebookCaption` puts the kit website on its own line before the hashtags; with no kit website the text has no link and the page says so (`NO_WEBSITE_NOTICE`). An off-range Facebook caption is stored with a notice, never refused. **Rate limit:** curate, regenerate and the other caption actions share a per-user window (`CAPTION_ACTIONS_PER_WINDOW` 30 per 10 minutes, `src/lib/captions/limits.ts`, built on `createWindowLimiter`), answered with 429 and `Retry-After`; under `MOCK_AI` it does not apply unless the seam `POST /api/test/caption-limit` sets an override (admin only, 404 in prod). Tiers: the two new routes are `edit` in `POST_ACTION_TIERS`. A curate passes the live general caption to the prompt, fenced as untrusted, and stores `generalHash` on the settle. `GET /api/drafts/[id]` returns `general` and `curated[]`. On the draft page the Refine Design card sits under the Preview card in the left column, and Captions is the right column.
- **Caption route (024):** a team's caption credential is a stored setting, `Team.captionRoute` (`CLI` or `API_KEY`; null means never chosen, which keeps the old rule: the brief's key, then the default COPY row, then the CLI). One pure selector, `selectRoute('CAPTION', input)` in `src/lib/models/route.ts`, decides the route and the row; `loadCaptionRoute` feeds it, `resolveCopyProvider` and `copyProviderIsClaude` call it, and `GET /api/team/caption-route` shows the same answer to `/team`. A chosen route with no usable credential **fails closed** with a route-named error and never falls to the other route or the server key. The route that ran is stamped on each caption row (general and curated alike) and the headline (`DraftCaption.route`, `Draft.headlineRoute`: `CLI`, `API_KEY`, `SERVER_KEY` or `OTHER`; null means before 024), and the `MOCK_AI` model-calls record carries it as `route`. An `API_KEY` run counts as the team credential tier for the Opus gate (`captionCredential` on `GET /api/models`). Under a chosen route a brief's stored `copyProviderKey` is `'cli'` and is ignored. `modelArgParity.test.ts` pins `apiId === cliArg` for every catalogue entry.
- **Analytics (006):** the app keeps an append-only event store in its own Postgres (`AnalyticsEvent`, plus `AnalyticsDrop` counters), written only through `track(name, fields)` in `src/lib/analytics/track.ts`. **One emitter per event name:** each event has exactly one place that writes it, and a shared function that serves several surfaces takes an explicit `source` (`web`, `mcp`, `acp`; `scheduler` is retired, listed in `RETIRED_SOURCES`). `track` never throws in production and is bounded at 2 s; a dropped or rejected event is counted in `AnalyticsDrop` and shown on the page. Under `MOCK_AI` or `NODE_ENV=test` an invalid payload throws. The catalogue (`src/lib/analytics/catalogue.ts`) holds each name's zod schema and `schemaVersion`; vocabularies (Prisma enums, model catalogue keys, 009 archetype keys) are **imported, not copied**, and `analyticsCoverage.test.ts` fails if a `DraftAction`, `Channel` or `source` value has no event that can carry it. A change that adds an action, a channel or a generation path owns its events. 037 retired `publish.settled` and `scheduled_generation.settled` (`RETIRED_EVENT_NAMES`) and added `draft.downloaded`, whose only emitter is the download route. Events hold ids, enums, counts, durations, redacted failure reasons and the capped refine instruction, never prompt text, model output, captions or headlines. `POST /api/events` takes only the client events `wizard.step` and `caption.copied` and sets team, user and source from the session. `caption.copied` (039; `{ kind, channel }` only, one emitter in the events route) is sent after a successful clipboard write; it needs a draft the caller may view (otherwise 404, nothing written), a registry kind and channel pair (otherwise 400), and a repeat for the same user, draft, kind and channel within 10 s is dropped and counted (`rate-limit`). It is **client-reported**: the Insights page labels the column that way, and a user can inflate it. `draft_action.settled` also carries `captionKind`, `captionOp` (`CAPTION_OPS`: `create` or `replace`) and `channel`. The Insights "Captions" section (super admin) shows written, failed and copied per registry entry, downloads and the curate rate. The read seam for tests is `/api/test/analytics-events` (404 in prod and without `MOCK_AI`, admin only). Reads go only through `src/lib/analytics/queries.ts`; the page is `/admin/insights`, super admin only. Retention is 180 days, swept by the worker's only loop (`retention`, 5 000 rows per tick). `scripts/purge-analytics.mjs` refuses to run without an explicit `DATABASE_URL`. New migration `20261024120000_analytics_events` (manual down script `prisma/rollback/006-product-observability.down.sql`); no env var.
- **Post styles (027):** a post style is code-owned data in `src/lib/postStyles/` (a sibling of `designData/`, which never imports it): eight styles (`general`, `launch`, `promotion`, `event`, `hiring`, `announcement`, `tip`, `milestone`), each with a goal, a default tone, a default image style and a checklist of measurable rules marked `caption` or `image`. **The key rule:** a key is never reused for a different meaning and never renamed; a retired style stays resolvable and is hidden from pickers; a future team-owned style gets its own id column. **The version rule:** a released version is never edited; add `versions[n+1]`. **One resolver:** `resolvePostStyle` (`resolve.ts`, pure) is the only place a style maps to a goal, tone, image style and checklist, and every surface calls it (wizard, `POST /api/briefs`, MCP, ACP, regenerate); `postStylesBoundary.test.ts` fails on any other mapping. Precedence is explicit style, project default, `general`. An unknown key is a 400 at write, never "no style". `UNATTENDED` surfaces are MCP and ACP. **`goal` is a snapshot** written only by the server from the style; a legacy `goal` with no `postStyle` picks `hiring`, `announcement` or `general`. **Stamps and versions:** `Draft.postStyle` and `DraftRevision.postStyle` hold `{ key, version, revision }`; `PROMPT_VERSION` and `CAPTION_PROMPT_VERSION` end in `+ps<POST_STYLES_REVISION>`, derived from the dataset; refine uses the stamped version. **The facts check** (`src/lib/factsCheck/`, pure, no model call, never throws) compares numbers, dates, times, currency, percentages and phone numbers in the headline, the general caption and every live curated caption (Instagram, LinkedIn, Facebook; a deleted one is skipped) with the brief, the project briefing, the kit voice text and the project documents (read from the draft's recorded `generationInputs`, not the project's current state; the sources are never a caption, and `factsSourcesBoundary.test.ts` fails if `sources.ts` reads captions), and stores `Draft.factsCheck` (`clear`, `flagged` or `error`; matched values and where, never text). It runs on every generation and recomputes on regenerate copy and on a caption or headline edit. The check never blocks anything: there is no hold rule since 037 (the queue and `Post` are gone). Known limits L1 to L7 are in the handoff 027 section; the check does not read the HTML. The "Post styles" section of `/admin/insights` shows chosen, generated and flagged per style. The ACP manifest is `2.2.0` since 039 (`2.1.0` since 038, `2.0.0` since 037). New migration `20261025120000_post_styles` (manual down script `prisma/rollback/027-post-styles.down.sql`); no env var.
- **Image looks (028):** a look is one key in `src/lib/designData/composition.ts`, with versions of contracts per size. Four looks are current: `product-showcase` (v2; SQUARE, PORTRAIT and STORY), `editorial-split` (v2; the same three sizes), `full-bleed-scene` (v1; a calm text band along the bottom) and `spotlight` (v2, current since 031 T18; a headline band at the top, a call-to-action band at the bottom, the subject centred; v1 stays resolvable for stamps and is kept as `SUPERSEDED_FIXTURES` in the render suite). Since post-style revision 12, Promotion and Milestone default to `spotlight` in the wizard (031 OP-031 passed 2 of 2). The geometry in the spec's FR-02 table is the only place a look declares a region. **The key rule:** a look key is never renamed and never reused for a different meaning; a retired look (`status: 'retired'`) stays in the dataset and still resolves for stamps, labels and refine, is hidden from the picker, and a new generation on it falls back to classic (`retired-classic` in the resolver). **The version rule:** a released version (the change that adds it is VERIFIED PASS) is never edited; a change is a new version. **`variantOf` is validation only,** and no variant ships. **The fixture set is the merge gate for the pixel check:** every current contract has one pass, one busy and one contrast fixture (36 in all, `tests/render/lookFixtures.ts`), and `lookFixtureCompleteness.test.ts` fails if the set drifts from the dataset. The fixtures prove the check discriminates; they do not prove that a real model image passes (NFR-11). **Unattended surfaces stay classic** (queue, MCP and ACP) through the resolver's `unattended-classic`. **The real-image check** is `scripts/look-check/run-look-check.mjs` (OP-028): one render per new contract, a hard cap of 16 calls enforced by the append-only `ledger.jsonl` in its fixed `--out` directory, which is never deleted. A look passes when every one of its contracts kept its style and the user accepted the render; that gates the interactive post-style defaults (T7) and nothing unattended. **OP-028 result (2026-10-25):** `full-bleed-scene` passed and `spotlight` failed, so T7 moved only Event and Hiring to `full-bleed-scene`; `lookCheckResults.test.ts` fails if a post-style version names a look that did not pass.
- **Product screenshots (025):** the `device-screen` look (v1, `requires: 'composite-source'`) is one landscape laptop whose blank screen is a `composite` region. It is offered only when the author has attached a screenshot. The screenshot is per post: the wizard uploads it (PNG, JPEG or WebP, checked by magic bytes) to the private `BUCKET_DOCS` under `screenshots/<teamId>/<userId>/`, and the brief stores `Brief.compositeSource` (migration `20261026120000_composite_source`). The image model draws a blank screen. `runHeroCheck` detects the screen (Amendment A1) and stamps `composites[].rect`; nothing re-detects after that. Code inserts one canonical `<div data-composite="0">` at the stamped rect, holding `<img src="__COMPOSITE_0__">`. The stored HTML only ever holds the token (NFR-05). The renderer resolves the token to a `data:` URI from the private object just before `setContent`, then checks the element in the page (loaded, within 2 px of the rect, topmost). A failure falls back to classic without the hero image (no second image call), with a named `composite-*` reason. A re-render (refine, override, inline edit, restore, export) that cannot place the screenshot fails with a named error and writes nothing. MCP and ACP posts never use it (`unattended-classic`).
- **Stale-headline badge (030):** `Draft.renderedText` and `DraftRevision.renderedText` (nullable JSONB, `{ headline: { text, verified, reason? } }`; null = rendered before 030, and it never shows a badge) record the headline a render visibly painted. The check runs in the same Chromium page as the PNG, inside `renderPost` (`src/lib/renderer/puppeteer.ts`): the FR-08 geometry (visible, inside the canvas, not clipped, topmost at each line centre), bounded at `HEADLINE_CHECK_TIMEOUT_MS` (5 s), and it never fails a render (a throw or timeout is `not-checked`). Under `MOCK_PUPPETEER` a text stand-in (`src/lib/renderedText/mockCheck.ts`) takes its place, and the sentinel `__MOCK_HEADLINE_HIDDEN__` in the brief topic yields `not-visible`. Every design writer stamps through `currentRenderStamp`'s required fourth argument; the writer guard is `tests/unit/renderedTextWriters.test.ts`. `headlineState` (`fresh`, `stale`, `unconfirmed`, `unknown`) is computed at read time from the stamp and `Draft.headline` and is never stored; a case-only or whitespace-only edit is `fresh`. The badge is `HeadlineImageNotice` on the draft page (Edit inline, Regenerate design). The Download button shows one non-blocking line under it (`downloadLineFor`); nothing blocks a download. Events: `draft.headline_edited` (one emitter, `trackHeadlineEdited`) and `generation.finished.headlineCheck`; none carries text (`publish.settled` is retired). Client components import `renderedText/noticeText` and `renderedText/vocab`, never the index: its stamp module uses `Prisma.DbNull`, which pulls `@prisma/client` into the browser bundle. Migration `20261027120000_rendered_text` (additive; down script `prisma/rollback/030-stale-headline-badge.down.sql`); no env var.
- **Brand-kit design rules (007):** the authoring dataset lives in `src/lib/designData/authoring/` (seven entries, the detector, the measurable check, validation, the role list). It is **not** re-exported by `designData/index.ts`, and `designDataBoundary.test.ts` fails if a generation-side file imports it. The detector picks every anchor; the model only fills wording inside an entry's ranges, and code builds each `Edit` and sets provenance (`dataset` or `unverified`; a reply's own provenance is ignored). Prompts name roles, never a hex or a font. The review logic is the host-agnostic pure reducer `src/lib/kitUpgrade/review.ts` (the hook and panel are in `src/components/textUpgrade/`). `POST …/prompts/upgrade` is team-admin only and logs `[kit-upgrade]`; Improve gains `lostRules`. The save route, `buildBrandKitSystemContext` and `PROMPT_VERSION` are unchanged (`generationUntouched.test.ts`). There is no stamp column (OQ-1).
- **API keys** stored AES-256-GCM encrypted; only `keyPrefix` shown in UI after registration; full key never returned
- **MinIO** served to browser via pre-signed URLs only — MinIO port never publicly exposed
- **Claude design agent** runs as a tool-use agent loop — tools: `generateImage`, `renderHtml`, `getBrandKitContext`
- **AGUI refinement:** natural language → Claude updates HTML → Puppeteer re-renders → `DraftRevision(htmlSnapshot)`
- **Brand kit structured data** (colors, fonts, logoUrl) is stored in the DB and passed to Claude as CSS variable definitions
